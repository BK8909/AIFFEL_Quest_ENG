# Full Stack Deep Learning - Day 2 제출

## Chapter 7 체크포인트

### 1. VS Code의 원격 개발 기능이 ML 엔지니어에게 왜 필수적인가요?

GPU 서버에서 실제 연산을 수행하면서 로컬 VS Code에서 코드 편집, 실행, 디버깅을 할 수 있기 때문입니다. 대규모 모델 학습은 로컬보다 원격 GPU 서버를 사용하는 경우가 많으므로 원격 개발 기능을 사용하면 작업 환경을 바꾸지 않고 서버 자원을 활용할 수 있습니다.

### 2. 주피터 노트북의 세 가지 문제점과 하이브리드 솔루션은 무엇인가요?

주피터 노트북은 셀 실행 순서에 따라 결과가 달라질 수 있고, 코드가 길어질수록 리팩토링이 어렵고, 출력까지 파일에 포함되어 Git에서 변경 내용을 비교하기 어렵습니다.

탐색과 시각화는 노트북에서 하고 모델, 데이터 처리, 학습 로직은 Python 모듈로 분리하는 방식이 적절합니다. 이렇게 하면 노트북의 편리함을 유지하면서 코드 재사용, 테스트, 버전 관리를 쉽게 할 수 있습니다.

### 3. 결정적 빌드가 보장되지 않으면 어떤 문제가 생기나요?

팀원마다 Python이나 라이브러리 버전이 달라져 같은 코드를 실행해도 결과가 다르거나 오류가 발생할 수 있습니다. 로컬에서는 실행되지만 다른 사람의 PC나 클라우드 서버에서는 실행되지 않는 문제가 생길 수 있습니다.

### 4. requirements.in과 requirements.txt의 역할 차이는 무엇인가요?

requirements.in에는 프로젝트에서 직접 사용하는 주요 라이브러리와 필요한 조건을 적습니다.

requirements.txt에는 실제 설치에 필요한 하위 의존성까지 포함해 정확한 버전을 고정합니다. 이 파일을 사용하면 다른 환경에서도 동일한 패키지 구성을 재현하기 쉽습니다.

## Chapter 8 체크포인트

### 1. Lightning으로 전환하면 직접 작성하지 않아도 되는 코드는 무엇인가요?

GPU 장치 이동, 학습과 검증 반복 루프, backward와 optimizer step 처리, 메트릭 집계와 로깅, 분산 학습과 체크포인트 관리 등을 Trainer가 대신 처리할 수 있습니다.

### 2. LightningDataModule의 setup과 train_dataloader의 차이는 무엇인가요?

setup은 데이터를 불러오고 학습, 검증, 테스트 데이터로 나누는 역할을 합니다.

train_dataloader는 준비된 학습 데이터셋을 배치 크기, 셔플, worker 수 등의 설정과 함께 DataLoader로 만드는 역할을 합니다.

데이터 구성과 로딩 설정을 분리하면 각각을 독립적으로 수정하고 재사용하기 쉽습니다.

### 3. shared_step 패턴은 어떻게 사용할 수 있나요?

forward 실행, loss 계산, 예측값과 정답 비교처럼 학습, 검증, 테스트에서 공통으로 사용하는 계산을 shared_step에 넣습니다.

training_step, validation_step, test_step에서는 같은 계산 결과를 사용하되 각 단계에 맞는 로그 이름과 반환값만 다르게 처리합니다.

### 4. overfit_batches=1 테스트가 실패하면 무엇을 확인해야 하나요?

첫째, 그래디언트가 제대로 계산되고 가중치가 실제로 업데이트되는지 확인합니다.

둘째, 입력 데이터와 레이블의 순서가 맞는지 샘플을 직접 확인합니다.

셋째, loss나 중간 값에 NaN이 발생하는지 확인하고 학습률이나 정밀도 설정을 점검합니다.

### 5. 실제 프로젝트에 맞게 Lightning 코드를 수정한다면 무엇을 바꿔야 하나요?

LitClassifier에서는 실제 문제에 맞게 입력 크기, 모델 구조, 출력 크기, loss 함수와 학습률을 수정해야 합니다.

MyDataModule의 setup에서는 실제 데이터셋을 불러오고 필요한 전처리와 학습, 검증, 테스트 분할을 적용해야 합니다.

## Chapter 9 체크포인트

### 1. 분산 학습에서 가장 중요한 GPU 지표는 무엇인가요?

분산 학습에서는 GPU 사이의 통신 속도를 결정하는 인터커넥트가 중요합니다.

각 GPU의 연산 능력이 넓은 고속도로라면 GPU 사이의 통신 구간은 톨게이트와 비슷합니다. 톨게이트가 좁으면 고속도로가 넓어도 전체 처리 속도가 느려질 수 있습니다.

### 2. GPU를 시간당 비용보다 실험당 비용으로 봐야 하는 이유는 무엇인가요?

시간당 가격이 낮아도 학습 시간이 길면 전체 비용이 더 커질 수 있기 때문입니다.

강의 예시에서는 구세대 GPU 4대가 시간당 약 24달러로 72시간 학습해 약 1,750달러가 들었지만, 최신 GPU 8대는 시간당 약 31달러여도 8시간 만에 끝나 약 250달러가 들었습니다.

따라서 GPU는 시간당 단가보다 한 번의 실험을 끝내는 데 필요한 총비용으로 비교하는 것이 적절합니다.

### 3. 스팟 인스턴스를 안전하게 사용하려면 무엇이 필요한가요?

스팟 인스턴스는 언제든 회수될 수 있으므로 체크포인트를 자동으로 자주 저장해야 합니다. 인스턴스가 중단된 뒤에도 마지막 체크포인트에서 학습을 이어서 시작할 수 있어야 합니다.

### 4. W&B가 있었다면 어떤 점이 편리했을까요?

학습률, 배치 크기, loss, accuracy 같은 실험 정보를 자동으로 기록하고 여러 실험 결과를 한 화면에서 비교할 수 있습니다. 어떤 설정으로 어떤 결과가 나왔는지 다시 확인하기도 쉬워집니다.

## Chapter 10 체크포인트

### 1. 스토리지 지연 시간이 DataLoader의 num_workers에 어떤 영향을 주나요?

스토리지가 느릴수록 GPU가 데이터를 기다리는 시간을 줄이기 위해 여러 worker가 다음 배치를 미리 읽어두는 것이 중요합니다.

다만 네트워크 저장소 자체가 매우 느리다면 worker 수만 늘리기보다 데이터를 GPU와 가까운 로컬 SSD에 두는 것이 더 효과적일 수 있습니다.

### 2. 이진 데이터는 객체 저장소에 두고 URL만 DB에 저장하는 이유는 무엇인가요?

이미지, 오디오, 비디오 같은 큰 이진 파일을 DB에 직접 저장하면 DB 성능과 백업, 복제 비용에 부담이 커질 수 있습니다.

파일 자체는 S3나 GCS 같은 객체 저장소에 두고 DB에는 파일 위치와 필요한 메타데이터만 저장하는 편이 효율적입니다.

### 3. OLTP와 OLAP의 차이는 무엇인가요?

OLTP는 행 지향 구조로 특정 사용자의 주문 조회나 개별 레코드 수정처럼 자주 읽고 쓰는 작업에 적합합니다.

OLAP는 열 지향 구조로 많은 데이터의 평균, 합계, 추세처럼 대규모 집계와 분석 작업에 적합합니다.

## Chapter 11 체크포인트

### 1. 레이블링을 최소화하는 네 가지 전략은 무엇인가요?

자기주도 학습은 데이터 자체의 구조를 이용해 별도 레이블 없이 표현을 학습하는 방식입니다.

데이터 증강은 기존 데이터의 의미를 유지하면서 형태를 바꿔 학습 데이터를 늘리는 방식입니다.

합성 데이터는 알고리즘이나 생성 모델을 이용해 새로운 학습 데이터를 만드는 방식입니다.

사용자 피드백은 클릭, 수정, 평가 같은 실제 사용자 행동을 레이블로 활용하는 방식입니다.

시니어 AI Assistant에는 합성 데이터와 사용자 피드백을 적용하기 좋다고 생각합니다.

### 2. 골드 표준 데이터셋이 필요한 이유는 무엇인가요?

엔지니어가 직접 정확하게 레이블링한 기준 데이터가 있어야 외부 레이블러의 결과 품질을 평가할 수 있습니다.

기준 데이터가 없으면 사람마다 다른 기준으로 레이블을 만들 수 있고 결과가 얼마나 정확한지 객관적으로 확인하기 어렵습니다.

### 3. 약지도 학습의 유지보수 측면 장점은 무엇인가요?

수동 레이블링은 레이블 체계가 바뀌면 기존 데이터를 다시 사람이 레이블링해야 합니다.

약지도 학습은 레이블링 함수의 규칙을 수정하고 다시 실행하면 많은 데이터의 레이블을 빠르게 갱신할 수 있어 유지보수가 쉽습니다.

### 4. LLM 합성 데이터는 언제 효과적이며 무엇을 주의해야 하나요?

많은 학습 예제가 필요하지만 직접 수집하거나 수동 레이블링하기 어려운 상황에서 효과적입니다.

다만 생성 데이터에는 오류, 편향, 중복이 포함될 수 있으므로 실제 데이터와 분포가 비슷한지 확인하고 품질 검증을 해야 합니다.

## Chapter 12 체크포인트

### 1. 현재 프로젝트의 데이터 버전 관리 수준과 다음 단계는 무엇인가요?

현재 실습 프로젝트는 데이터 버전을 별도로 기록하지 않는 경우가 많아 Level 0에 가깝습니다.

한 단계 올리려면 학습에 사용한 데이터 스냅샷을 시점별로 남겨 어떤 데이터로 학습했는지 다시 확인할 수 있게 해야 합니다. 이후에는 파일 위치와 라벨 같은 메타데이터를 Git으로 관리하는 Level 2 방식으로 발전시키는 것이 좋습니다.

### 2. 데이터 버전 관리 없이 모델을 롤백하면 어떤 문제가 생기나요?

모델 성능이 떨어져 코드를 이전 버전으로 되돌려도 당시 사용한 데이터가 남아 있지 않으면 같은 모델을 다시 만들 수 없습니다.

코드가 같아도 학습 데이터가 달라지면 결과 모델도 달라지므로 정확한 재현이 어렵습니다.

### 3. Level 2의 장부 비유를 설명해 보세요.

큰 이미지나 오디오 파일 자체를 Git으로 관리하는 대신 파일이 저장된 위치와 라벨을 적은 목록을 버전 관리하는 방식입니다.

이 목록의 과거 버전으로 돌아가면 당시 어떤 데이터를 사용했는지 다시 확인하고 데이터셋을 재구성할 수 있습니다.

### 4. 워크플로우 자동화는 언제 필요하나요?

몇 단계만 가끔 수동으로 실행하는 작은 실험은 단순한 Python 스크립트로 충분합니다.

데이터 수집, 전처리, 학습, 평가 같은 여러 작업이 정해진 순서로 반복되고 실패 처리, 재시도, 모니터링이 필요해지면 Airflow 같은 전문 도구가 필요합니다.

# Day 2 통합 체크포인트

### 1. 재현 가능한 환경을 팀원에게 전달하려면 무엇이 필요한가요?

Python과 주요 라이브러리 버전을 고정해야 합니다.

requirements.in과 버전이 잠긴 requirements.txt를 함께 관리하고, 필요한 경우 Conda나 uv 설정 파일과 Makefile까지 포함하면 팀원이 같은 환경을 재현하기 쉽습니다.

### 2. 기존 PyTorch 코드를 Lightning으로 리팩토링한다면 어떻게 나눌 수 있나요?

모델 구조, forward, loss 계산은 LightningModule에 넣습니다.

training_step에는 학습 배치의 forward, loss, metric 계산을 넣고 validation_step에는 검증 loss와 metric 계산을 넣습니다.

configure_optimizers에는 optimizer와 scheduler를 정의합니다.

GPU 수, mixed precision, epoch 수, checkpoint, early stopping 같은 실행 설정은 Trainer에서 관리합니다.

### 3. Day 1에서 기획한 프로젝트의 인프라는 어떻게 구성할 수 있나요?

시니어 AI Assistant의 초기 실험은 단일 GPU 환경으로 시작하고, 실제 서비스 배포와 안정성이 중요해지면 GCP 같은 클라우드를 사용할 수 있습니다.

모델 크기에 따라 충분한 VRAM을 가진 GPU를 선택하고 실험 기록은 W&B로 관리합니다. 초기 단계에서는 고정 GPU를 사용하고, 체크포인트와 학습 재개가 안정화되면 스팟 인스턴스를 이용해 비용을 줄일 수 있습니다.

정확한 비용은 모델 크기와 학습 시간에 따라 달라지므로 실제 후보 GPU의 시간당 가격과 예상 학습 시간을 곱해 실험당 비용으로 계산해야 합니다.

### 4. 같은 프로젝트의 데이터는 어떻게 확보하고 관리할 수 있나요?

초기에는 공개 데이터와 직접 수집한 문자, 이미지 데이터를 사용하고 부족한 부분은 데이터 증강이나 LLM 합성 데이터로 보완할 수 있습니다.

서비스가 운영되면 사용자의 수정, 도움 여부, 자녀에게 전달한 행동 같은 피드백을 새로운 레이블로 활용할 수 있습니다.

데이터 버전 관리는 최소 Level 1에서 시작하고, 가능하면 파일 위치와 라벨 같은 메타데이터를 Git으로 관리하는 Level 2로 발전시키는 것이 좋습니다.

### 5. GPU 비용을 시간당 비용과 실험당 비용으로 비교해 보세요.

시간당 비용만 보면 저렴한 GPU가 유리해 보이지만 학습 시간이 길면 전체 실험 비용은 더 커질 수 있습니다.

강의 예시처럼 시간당 약 24달러인 구세대 GPU 구성이 72시간 필요하면 약 1,750달러가 들지만, 시간당 약 31달러인 최신 GPU 구성이 8시간 만에 끝나면 약 250달러로 더 저렴할 수 있습니다.

스팟 인스턴스는 자동 체크포인트 저장과 학습 재개 기능이 준비되어 있을 때 사용하는 것이 안전합니다.
